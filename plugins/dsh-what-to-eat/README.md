# 今日美食 · dsh-what-to-eat

按你配置的时间，从本地家常菜库里**加权随机**抽一道菜推给你。右侧栏有常驻面板，会话里有同一份数据驱动的卡片——两处读写同一个库、同一次抽取结果，改一边另一边立刻跟着变。

- 不联网、不抓取任何平台内容、不调用模型、不新建会话。
- 内置 214 道菜（家常 182 / 外卖 109 / 减脂 58 / 快手 35 / 放纵 30；一道菜可同时属于多个场景），含餐次、标签、简短做法，可直接用，也可整库替换。
- 数据只存在本机，卸载后可在面板里一键清空。

## 装好之后

1. 右侧栏出现「今日美食」tab（点卡片上的「面板」按钮打开；关掉后可从右侧栏的 `+` 里再打开）。
2. 默认三个档位：早餐 07:30、午餐 11:40、晚餐 17:40，每天。
3. 到点后会话输入框上方出现一张卡片：菜名 + 标签，有做法可展开；模式②还会带「看攻略」。

## 两种模式

| 模式 | 卡片内容 |
|---|---|
| ① 只推菜名 | 菜名 + 标签，有条目做法时可展开 |
| ② 菜名 + 攻略 | 在此基础上多一个「看攻略」按钮 |

模式是**全局默认 + 每档可覆盖**。攻略链接取值优先级：

1. 条目自带的 `guide.url`；
2. 按配置的搜索模板生成深链（默认下厨房 `https://www.xiachufang.com/search/?keyword={q}`）；
3. 在面板里把某条改成自己的链接。

生成的一律是**搜索结果页**，不是具体帖子——插件不解析也不挑选平台内容。

## 抽取规则

1. **忌口优先**：`忌口标签` 命中的条目**完全不入抽取池**（不是降权）。
2. **喜好加权**：命中 `喜好标签` 的条目权重 × `喜好权重倍数`（默认 2.2），其余按基础权重。
3. **时间窗口**：默认剔掉最近 7 天内推过的条目。
4. **同餐次当日不重复**：同一天、同一餐次内不重复抽到同一条。
5. **逐级放宽**：池子不够时按 `N 天 → ⌈N/2⌉ 天 → 0 天` 逐级放开，**不禁止重复，只降权**（刚吃过的菜权重 ×0.2～0.7）；卡片上会标「已放宽去重」。
6. 每次抽 1 条，可改成 3 条候选（全局默认值，可在单个档位上覆盖）。

> 放宽策略是按「宁可重样，也不空手」定的：池子只有 5 道菜、去重窗口 7 天时，第 6 天开始必然抽不到新菜。此时插件会放宽窗口并在卡片上明示，而不是当天什么都不推。

## 时间与补发

- 时间表是配置数据，面板里可增删改：星期 / 时间 / 餐次 / 模式 / 开关。
- 用本机时区；同一档位同一天只推一次（状态落盘，重启不重复）。
- **错过 30 分钟内补推**（可改）：应用没运行或休眠时错过的档位，回来后在窗口内照常推，卡片标「补发」；超出窗口记为「已错过」，只在面板历史里留痕。
- **静默时段**：静默内到点的档位会顺延到静默结束再推，标「补发」，并且不再受 30 分钟窗口限制（延迟是你自己设的，不算错过）。档位时间本身落在静默里时，面板会给出提示。
- **跨午夜**：23:59 这种档位如果在 00:00 之后才醒，会按「前一天」补推（归到前一天的历史与去重账上），不会因为「今天 23:59 还没到」而被吞掉。
- **没有活动会话时**：不新建会话、不弹任何东西，只更新面板；下次打开会话时，当天最近的那一次结果以卡片形式补上并标「补发」，更早的档位只留在面板历史里（不会一次刷三条）。
  「有没有会话」按会话里的卡片心跳判断：只开着侧栏面板、没打开对话，也算没有会话。

## 面板

- **今天**：当前结果、换一道、今日历史、池子告警。
- **菜库**：搜索、按启用状态 / 餐次 / 场景 / 标签筛选（标签按出现次数排序，可多选，一键清空筛选）、增删改、单条停用（停用保留数据但不抽）。
- **时间表**：档位增删改与开关。
- **设置**：默认模式、候选数、去重窗口、补推窗口、静默时段、喜好/忌口标签、搜索模板、导入导出、清空历史、**重置为出厂状态**。

### 导入

支持三种来源，**默认同名跳过**：

- JSON：`[{ "name": "...", "meal": ["L"], "tags": ["辣"], "recipe": "...", "guide": { "url": "" } }]`
- CSV：`name,meal,tags,recipe,url,weight,disabled`
- 一行一个菜名（也可以写 `菜名,餐次,标签`）

导入前先出**预览**（新增几条、同名跳过几条、字段冲突几条、格式错误），确认后才写入；写入前会存快照，面板里可**撤销上一步**（导入或删除）。

### 导出

`设置 → 导出` 可导出 JSON 或 CSV，导出文件可直接再导入。

## 数据与隐私

- 库、时间表、历史、去重状态都写在 `$DSH_HOME/what-to-eat/state.json`（Windows 默认 `C:\Users\<你>\.dsh\what-to-eat\state.json`）。
- 不联网、不上传、不采集，也没有任何模型调用。
- **卸载说明**：DSH 的 storage 机制不会替插件删数据，卸载后这个 JSON 会留着。要彻底清理，先在面板里点「重置为出厂状态」（回到内置库、默认档位、无历史），再删掉 `what-to-eat` 目录即可。

## 面板不出现时先看这里

在浏览器里打开 `http://<你的 DSH 地址>/dsh-what-to-eat/api/state`，看 `diag`：

```json
"diag": { "clientVersion": "0.1.1", "slots": { "card": true, "tabType": true, "panel": true } }
```

- 没有 `diag` 字段 → 客户端模块没被页面加载（多半是没重启/没刷新，或插件没启用）
- `slots.tabType=false` → 侧栏页类型注册失败
- `slots.panel=false` → 面板正文注册失败（侧栏还没声明那个 keyed slot）
- `slots.card=false` → 会话卡片注册失败

这个接口不需要登录，直接访问即可。

| 项 | 值 |
|---|---|
| DSH | `0.2.1-rc.2` 实测兼容；声明范围 `>=0.2.0-rc.1 <0.3.0-0` |

## 权限与外部依赖

| 项 | 情况 |
|---|---|
| 网络 | **无 outgoing 请求**。只在本机 DSH 的 webserver 上注册 `/dsh-what-to-eat/api` 前缀路由，供自己的前端调用。 |
| 文件 | 读写 `$DSH_HOME/what-to-eat/state.json`（库、时间表、历史、去重状态）。不碰其他文件。 |
| 命令 | 不执行任何子进程或 shell 命令。 |
| 凭据 | 不读取、不存储任何凭据。 |
| 生命周期脚本 | 无 `preinstall` / `install` / `postinstall` / `prepare`。 |
| 运行时依赖 | 无（只用 Node 内置模块；前端 `react` 由宿主模块表提供）。 |
| 模型调用 | 无。 |

## 已知边界

- 会话卡片是**全局常驻的浮动卡片**（挂在 shell 浮层里，切会话、到欢迎页都在），`position: fixed` 不占任何布局，**不写入会话日志**。后者是刻意的：DSH 不允许插件向会话追加自定义事件类型（未知类型会让会话无法重新打开，官方的 `appendPluginRecord` 又只允许实验包调用）。
- **右侧栏面板不会自动出现**：只有点卡片顶栏的「面板」按钮（或菜名）才会打开它；关掉之后它也不会再自己回来。
- 卡片**可以拖动**（按住顶栏拖），拖到离左右边缘 40px 以内会**自动贴边收起**成一条窄条；点窄条展开。位置和收起状态记在本地，刷新后保持。顶栏的 `–` 可以直接贴边，`×` 是这条不再打扰。
- 卡片的菜名可以点：点了会打开右侧栏的面板（侧栏被折叠时的快捷入口）。
- 卡片的显示判定是「当天最近一次结果 + 这份关闭记忆」：关掉卡片后同一条不会再打扰你，下一次抽取生成新卡片时再出现。
- 三处 UI 文案（面板、卡片、插件元信息）自带中英两套；面板语言跟随页面语言。

## 开发

```bash
node test/engine.test.mjs            # 抽取引擎单测（15 项，毫秒级）
node test/host.integration.mjs       # Host 集成测试（真持久化 / 真定时器 / 真 HTTP，约 50 秒）
node test/midnight.integration.mjs   # 跨午夜补推（伪造时钟，约 45 秒）
```

集成测试用临时 `DSH_HOME` 起一份 Host，不会碰你的真实菜库。
